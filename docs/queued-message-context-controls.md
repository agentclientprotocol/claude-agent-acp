# Queued prompt cancellation and context diagnostics

Both ACP versions advertise `_meta.runtime` version 1. This extension exposes
only reads `context`, `queuedMessages`, and control `cancelQueuedMessage`.
It is independent of conversation/file rewind, MCP replacement and runtime reload.

## Pending prompt snapshot

```json
{ "sessionId": "s", "resource": "queuedMessages" }
```

Send to `_session/runtime/read`. Success data is
`{ "messages": [{ "messageId": "uuid" }] }`. IDs belong to pending adapter
prompts in this live session; contents are omitted. Active, inserted, started,
finished and steered prompts are excluded. This is an observed snapshot: a
message can be dequeued before a later control reaches the CLI.

## Cancel exactly one pending prompt

```json
{ "sessionId": "s", "action": "cancelQueuedMessage", "messageId": "uuid" }
```

Send to `_session/runtime/control`. Success data is
`{ "messageId": "uuid", "cancelled": true }` or the same object with `false`.
Only native `true` confirms a drop. The pending prompt ends with `cancelled`
without usage; other prompts continue. Native `false` preserves its ordinary
lifecycle (already dequeued, absent, or still buffered before the native queue).
A missing SDK method returns `unavailable/unsupported`. Unknown or non-pending
IDs and bulk/reorder/promote fields are invalid parameters.

The terminal `cancelled` lifecycle frame can arrive before the ACK. A target
that has not started is settled immediately at that frame, preventing another
prompt's echo-less result from being assigned to it. When session/cancel races
this request, its orphan debt is reconciled once, regardless of ACK/interrupt
receipt order. A new activation resets the debt generation.

Malformed/rejected ACKs, contradictory execution evidence, request cancellation
or the 15-second mutation deadline leave the native outcome uncertain. The
adapter closes that query, ends unresolved prompts as failed, and waits for the
actual process exit before releasing its lifecycle reservation. These error
paths can end the whole session; they never report a successful single drop.
An unconfirmed exit fences same-ID recreation until the ACP connection is
replaced. Duplicate controls, prompt admission, steering, load/resume,
close/delete/dispose and provider recreation share the reservation. Cancellation
remains callable while a provider change waits for accepted turns to finish.

## Context summary and explicit full diagnostics

```json
{ "sessionId": "s", "resource": "context" }
```

Omitted detail always sends `{ "detail": "summary" }` to the SDK, whose own
default is full. Explicit `"detail": "full"` requests per-category token counts;
`"detail": "summary"` requests estimates. No other resource accepts detail.
Invalid values and extra fields fail before native dispatch.

Full diagnostics may send token-count requests using this session's provider
credentials. Discovery advertises `fullMayUseNetwork: true`. Full is never
selected automatically or persisted as the default. There is no adapter retry,
fallback or background full refresh. Native category data is returned as-is.
Reads have a five-second dispatch deadline, reject stale query results, and
observe cancellation. Discarding a read does not cancel already dispatched
native counting traffic. Waiting for an existing lifecycle reservation can add
time before dispatch. No model prompt is generated by either read.

## SDK maintenance and validation

The dependency remains pinned to Agent SDK 0.3.293. `sdk.mjs` implements
`cancelAsyncMessage(uuid)` outside the public `Query` type and returns
`response.cancelled`. The small bridge feature-detects callability, preserves
`this`, and requires a boolean. The SDK's `getContextUsage` public documentation
states that full invokes the token-count API and summary uses local estimates.
Shutdown confirmation uses private `transport.waitForExit` (and async disposal
when present). Recheck these contracts when updating the SDK.

Run:

```sh
npm run check
npm run build
npm run test:run
node scripts/native/e2e.mjs
```

The native suite has only `queue-cancel`, `context-full`, and `sdk-contract`.
It starts the real SDK/CLI against a loopback fake streaming provider and fake
count_tokens endpoint, with a dummy key, temporary HOME/config/workspace,
empty setting sources, tools disabled, hooks/memory disabled, and local denying
proxies. It does not use real accounts or models. This environment isolation is
not an OS network sandbox. CI runs these three cases after the unit suite.

`queue-cancel` holds the foreground response, waits for two native queued frames,
drops one, and checks pending ACP completion, surviving work and provider history.
`context-full` checks summary/invalid requests cause no counting, explicit full
reaches the fake counter, and authored history stays unchanged. Counts are fake,
not tokenizer accuracy. Empty tools/memory do not test every possible category.
`sdk-contract` checks absent/dequeued false ACKs and actual process exit. ACP v2
is covered through real protocol routers with fake Queries; native tests use v1.
The real-CLI false dequeue race is not forced by the queue scenario.

Inject wrong provider text to verify the assertions fail:

```sh
node scripts/native/e2e.mjs queue-cancel context-full --inject-wrong-reply
```

## 中文说明

两个 ACP 版本统一声明 `_meta.runtime`，本扩展仅提供 `context`、
`queuedMessages` 读取和 `cancelQueuedMessage` 单条撤回，不依赖 rewind/MCP/reload。

排队列表只包含当前会话尚未开始的普通 prompt ID，不含正文；这是瞬时快照。
单条撤回只接受其中一个 ID。原生布尔 `true` 才确认撤回并结束该 prompt，
不附带其他消息的 usage；`false` 表示未撤回，继续正常生命周期。缺少 SDK
私有方法返回 unsupported；未知 ID、批量、重排和提升字段均拒绝。

原生 cancelled 帧可能先于 ACK。尚未开始的目标在此帧到达时即结束，避免
后续无 echo 结果错配。与全会话取消交错时，按代次和 receipt/ACK 顺序核销
孤儿结果债务，避免重复扣减。未知、失败或矛盾 ACK，以及控制取消/15 秒超时，
会关闭整条 Query、使未结束 prompt 失败，并等待原生进程退出；不会伪报成功。
退出无法确认时禁止同 ID 重建，需要重新连接 ACP。这些异常路径会影响整个会话。

context 不传 detail 时明确使用 summary；仅显式 full 才请求完整分类计数。
full 可能使用当前提供商凭据发起 token-count 网络请求，能力声明会提示。
无自动 full、适配器重试、回退或定时刷新。参数非法时不调用原生计数。
读取派发后五秒超时或取消只丢弃返回值，不能保证终止已发送的计数流量；
等待会话锁的时间另计。读取不会生成模型 prompt。

验证使用假 Query 和真实协议路由；原生三项用例使用真实 SDK/CLI 连接本机
loopback 假模型及假计数端点，隔离 HOME/config/workspace，不使用真实账号、
模型或全局设置。此环境隔离不等同系统级网络沙箱。假 token 数不代表真实分词
精度，空工具/记忆配置也不代表所有分类已验证。升级 SDK 时必须重跑私有撤回、
实际进程退出及 summary/full 合同测试。
